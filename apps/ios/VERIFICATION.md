## Что ещё не проверено

- **Полная компиляция SwiftUI с Apple SDK, линковка, упаковка IPA и подпись.** Экраны могут потребовать исправлений после первого Apple typecheck.
- Установка через xtool, физический iPhone и iOS Simulator.
- Снимки настоящих SwiftUI-экранов и визуальное совпадение с мобильным вебом.
- Клавиатура, safe area, VoiceOver/Dynamic Type, поворот, плавность, drag/resize/drop/cancel, фокус и позиции на iOS 17.6.1.
- Keychain, фоновые снимки, системные разрешения и уведомления на устройстве.
- Синхронизация запущенного iPhone-клиента с production и одновременно открытым вебом; реальный Google OAuth/CRUD, Telegram и ИИ-провайдер.

**HTML-макет для просмотра дизайна.** `preview/index.html` обновлён до шести разделов. В браузере проверены переходы, светлая и тёмная темы, отображение календаря, привычек, финансов и настроек, демонстрационный ответ помощника, создание задачи. Модули также прошли синтаксическую проверку Node и локальные проверки расчётов на вымышленных данных. Это отдельное представление дизайна: SwiftUI, физический iPhone и API этим не проверены. Сервер слушает loopback; CSP запрещает внешние подключения.

5. Привычки: история расписания, 1/1 = 100%, количество, прошлые даты, серия, heatmap, архив/возврат/удаление, конкурентное изменение с веба.
6. Финансы: шесть типов, валюты/даты, переводы и балансы, price update, удаление, конфликт версии. Использовать явно тестовые записи.
7. ИИ: новый/старый/удалённый на другом устройстве диалог, длинный ответ, ручной retry с тем же ID, идея/обсуждение, применение/отклонение/отмена предложений.
8. Настройки: несохранённый ввод при refresh, тема/язык, Google через браузер, Telegram, разрешение уведомлений и отключение при failed follow-up read.
9. Утерянный ответ записи не должен автоматически создавать дубль; после восстановления связи пользователь сверяет актуальные данные перед повтором.

## Ограничения архитектуры

Google-подключение требует входа на сайте в системном браузере; прямого native OAuth handoff ещё нет. Нет APNs, постоянного фонового poller, дискового offline-кэша и offline-очереди. Локальные уведомления ограничены сессией. API локальных задач не предоставляет optimistic version guard.

Исходники подготовлены для передачи через отдельную GitHub-ветку `codex/ritm-native-ios`: `apps/ios`, серверный контрактный тест и запрет автоматического Vercel-деплоя этой ветки в vercel.json. По отдельному запросу владельца ветка публикуется без PR и изменения main. База и аккаунт не изменяются. Контрактный тест повторно пройден перед публикацией; первоначальный запуск в песочнице блокировался EACCES для loopback, повтор вне этого ограничения прошёл.
