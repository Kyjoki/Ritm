# Ritm для iPhone — SwiftUI-клиент

Цель: перенести мобильную веб-версию Ritm в нативное приложение для **iPhone 13**, сохранив функции и максимально близко повторив дизайн. Пользователь выбрал SwiftUI. WKWebView не используется как оболочка. Минимальная версия — iOS 27 (см. `Package.swift`); установка позднее через xtool.

**Текущий результат — расширенные исходники, а не проверенный IPA.** Переносимое ядро собрано и протестировано настоящим Swift-компилятором. Для SwiftUI ещё нужны Apple SDK, полная сборка и проверка на устройстве. Для просмотра дизайна добавлен отдельный интерактивный HTML-макет всех шести разделов в рамке iPhone. Он не запускает SwiftUI и не подтверждает нативный рендер.

## Разделы в нативных исходниках

| Раздел      | Экраны и действия                                                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Мой день    | Прогресс, ближайшее событие, свободное время, задачи сегодня/завтра, создание и редактирование, расписание, недельный трекер привычек, переход к помощнику    |
| Календарь   | День/неделя/месяц, локальные задачи и Google-события, CRUD, повторы, выполнение задач, восстановление/перенос, drag-and-drop и изменение длительности         |
| Привычки    | Неделя/месяц, дуга прогресса, столбцы, карта регулярности, серии и сравнение периодов, история и количественные отметки, формы, архив/восстановление/удаление |
| ИИ-помощник | Диалоги, чат, разбор идеи и обсуждение, предложения с выбором и подтверждением, отклонение, отмена применённого изменения                                     |
| Финансы     | Счета, доходы, расходы, депозиты, акции и переводы; CRUD, отдельные валюты, даты и графики из реальных данных                                                 |
| Настройки   | Профиль, язык, часовой пояс, рабочие часы, темы, уведомления, Google/OpenAI/Telegram, синхронизация и выход                                                   |

Лавандовые темы, фон, стеклянные карточки с одним контуром, логотип и плавающая навигация реализованы нативно. Четыре главных раздела и «Ещё» сохраняют доступ ко всем шести страницам. Посещённые разделы удерживают позицию и черновики. Анимации учитывают Reduce Motion; материалы — Reduce Transparency и повышенный контраст.

Системные формы, клавиатура, выбор даты и SF Symbols могут отличаться от браузера. Календарь устроен как в Google Calendar: вид (расписание, день, 3 дня, неделя, месяц) выбирается в боковом меню, период листается свайпом или выбором даты в мини-месяце, а открывается он всегда на неделе (последний вид не запоминается). У маленького события длительность меняется в редакторе, у достаточно большого — также ручкой. Совпадение по пикселям пока не подтверждено.

## Данные и безопасность

- Используется существующий HTTPS API, общий с вебом (по умолчанию `ritm-eta-hazel.vercel.app`). Адрес меняется в Настройки → «Адрес сервера» (отдельной страницы входа нет, форма входа находится в Настройках): только https, проверка через `GET /api/health`, смена выходит из аккаунта на этом iPhone. Для адреса, отличного от адреса по умолчанию, перед сохранением показывается предупреждение «Вход и данные будут отправлены на этот сервер», а форма входа напоминает о нём; приложение никогда само не входит на такой сервер. Сессия в Keychain отдельная для каждого сервера. Новая база и миграции не создавались.
- Сессия устройства хранится в Keychain с `WhenUnlockedThisDeviceOnly`, без iCloud. Пароль и коды не сохраняются и не пишутся в журнал; сохранённые прежними сборками логин и пароль удаляются из Keychain при запуске. URLSession изолирован от общих cookies/кэша; redirects запрещены.
- Вход идёт с `client: "ios"` и `deviceName` («iPhone (модель)», без имени владельца) и даёт долгую отзываемую сессию устройства: продлевается при каждом использовании и заканчивается только после года без входа в приложение, выхода вручную или «Выйти на всех других устройствах» на сайте (технический предел 10 лет). Приложение принимает cookie сессии не длиннее 10 лет. Когда сессия истекла или отозвана (401 `AUTH_REQUIRED`), память очищается, показывается плашка «Войдите в аккаунт в Настройках» и форма входа; автоматического повторного входа нет. Фоновые снимки закрываются экраном Ritm.
- Второй фактор: если сервер отвечает 401 `TOTP_REQUIRED`, форма входа просит 6-значный код (или код восстановления); `TOTP_INVALID` показывает ошибку, 429 — время ожидания. Включается вход с кодом на сайте (Настройки → Безопасность).
- Настройки → «Безопасность» (`GET /api/security`): состояние входа с кодом, список устройств («Это устройство»), «Выйти» для другого устройства (`DELETE /api/security/sessions/:id`) и «Выйти на всех других устройствах» с подтверждением (`POST /api/security/sessions/revoke-others`). Если сервер старый и отвечает 404, карточка скрыта.
- Обновление после записи, при возвращении, вручную и каждые 30 секунд в активном состоянии. Старый ответ не должен заменять результат новой операции.
- Записи сериализованы и не повторяются автоматически после неопределённого сетевого результата. Перед повтором пользователь сверяет данные.
- Привычки/финансы используют `expectedUpdatedAt`, Google — ETag и идентификаторы подключения; создание события — устойчивый request ID. У API локальных задач нет проверки версии: это ограничение сервера.
- Разные валюты не складываются; финансовые записи не попадают в контекст ИИ. Предложения ИИ применяются только после выбора и подтверждения.
- Секреты интеграций отправляются только на сервер и не сохраняются локально; поля секретов очищаются при уходе в фон и закрытии формы.

Офлайн-очереди нет. Последние данные живут только в памяти процесса; при холодном запуске без сети вход не обходится. Тесты не заменяют проверку реального Keychain, URLSession и синхронизации двух запущенных клиентов.

## Особенности интеграций

**Google OAuth.** Существующее подключение используется нативно, включая запись. Подключение/расширение прав открывает настройки сайта в SFSafariViewController: пользователь при необходимости входит там, проходит Google и нажимает «Готово». Серверный OAuth привязан к браузерной correlation-cookie. Сессия не передаётся через URL. Для прямого возврата из Google в приложение нужен отдельный серверный handoff; он не внедрялся в production.

**Уведомления.** Локальное планирование после разрешения iOS использует последние полученные задачи и ограничено текущей сессией. Это не APNs и не непрерывная синхронизация в фоне. Telegram остаётся серверной интеграцией существующего Ritm.

```text
apps/ios/
  Package.swift                    Ritm + переносимое ядро RitmCore
  Info.plist, xtool.yml             упаковка и Bundle ID (iOS 27 задаётся в Package.swift)
  Resources/AppIcon.png             существующий фирменный значок Ritm

  Sources/Ritm/                     SwiftUI, состояние, Keychain (сессия), безопасность, уведомления

  preview/                         интерактивный HTML-макет шести разделов, не SwiftUI
```

## Проверка

Из `apps/ios`, с установленным Swift 6+:

```sh
RITM_CORE_TESTS_ONLY=1 swift test
```

В PowerShell перед `swift test` задайте `$env:RITM_CORE_TESTS_ONLY='1'`, затем удалите переменную. Для сборки приложения она не должна быть включена.

На этом компьютере переносимый Swift 6.4.1 установлен в WSL Ubuntu, в `/var/tmp/ritm-swift-toolchain/swift-6.4.1-RELEASE-ubuntu26.04/usr/bin/`. Ядро проверяется отдельно, без SwiftUI/Apple SDK. Из корня репозитория на Node 24:

```sh
node --import tsx --test tests/*.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build --configLoader runner
```

`tests/native-client-contract.test.ts` поднимает временный локальный сервер: две сессии, общие данные, конфликт привычки, отклонение чужого Origin, независимый выход. Production и реальные Google/OpenAI/Telegram запросы в тестах не используются.

## Просмотр дизайна до установки

Из корня репозитория выполните `node apps/ios/preview/serve.mjs` и откройте выведенный адрес `127.0.0.1`. Сервер доступен только на этом компьютере.

Макет содержит все шесть разделов, светлую/тёмную темы, размеры экрана 375/390/430 px, формы и переходы. Можно менять задачи, привычки и финансовые записи, смотреть демонстрационный ответ помощника. Все данные вымышленные и живут только в памяти страницы; обновление или «Сбросить макет» возвращает исходный пример. CSP запрещает сетевые подключения, интеграции не запрашивают ключи. Это инструмент обсуждения дизайна, а не запуск iOS-приложения: системная клавиатура, жесты, SwiftUI и реальная синхронизация проверяются отдельно.

## Позже: сборка и установка через xtool

Сначала пользователь вносит корректировки. Сейчас нет подписанного IPA, регистрации устройства или установленного приложения.

1. Настроить Apple SDK и xtool по [официальной инструкции Windows/WSL](https://github.com/xtool-org/xtool/blob/main/Documentation/xtool.docc/Installation-Linux.md).
   На этом компьютере уже стоят Swift 6.4.1 и xtool 1.24.0 в WSL (`~/.local/bin/xtool`, SHA-256 сверен с релизом GitHub). Не хватает только SDK: владелец сам скачивает **Xcode 27.1** (`.xip`) с developer.apple.com под своим Apple ID. Для сборки без подписи вход в Apple ID в xtool не нужен:
   ```bash
   xtool sdk install /mnt/c/Users/Maksim/Downloads/Xcode_27.1.xip
   cd apps/ios && xtool dev build
   ```
   `xtool dev build` без `--sign` только компилирует `.app`: на iPhone ничего не ставится.
2. Выполнить полную сборку, исправить ошибки Apple SDK/SwiftUI, проверить ресурсы, App Icon и Bundle ID `app.ritm.personal` для своего Apple Developer Team.
3. Настроить подпись локально и выполнить `xtool dev` из `apps/ios`, когда можно установить приложение. Пароли и ключи Apple не отправлять в чат/Git.
4. Пройти сценарии из `VERIFICATION.md` на iPhone 13 и сверить все экраны с вебом в обеих темах.

Передача исходников: отдельная ветка `codex/ritm-native-ios` в GitHub. Web/server-код и main не изменяются. Для этой ветки автоматические Vercel deployments отключены в vercel.json; production не публикуется.
