# Обзор реализации Ritm

Дата: 13 октября 2026 года. Lead/UX-обзор выполнен по исходникам четырёх разделов, клиентским контрактам, стилям и календарным тестам. Основа оформления — утверждённые фиолетовые темы из `design/approved-preview.html`; цвета вынесены в `src/styles/tokens.css`.

## Проверенные сценарии

| Сценарий            | Подтверждение                                                                                                                                                                                                                                                                                                         |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Мой день            | Реальные задачи, прогресс, расписание, просроченные и записи без даты. Создание, редактирование, выполнение и отмена обращаются к API.                                                                                                                                                                                |
| Календарь           | День, неделя, месяц, переход между периодами и «Сегодня». Свободный интервал передаёт дату/время в форму; запись открывает редактирование. Длительность определяет высоту блока; пересечения раскладываются по колонкам.                                                                                              |
| Мобильный календарь | По умолчанию повестка дня. Неделя отображается списком дней. Месяц содержит кнопки дней с доступным описанием количества записей; декоративные точки не получают фокус. Свободные интервалы позволяют создать помещающуюся запись.                                                                                    |
| Повторение          | Ежедневные, еженедельные и ежемесячные серии начинаются с выбранной даты. Выполнение хранится в `completedDates` и относится к экземпляру; редактирование и удаление относятся к серии и сопровождаются пояснением.                                                                                                   |
| ИИ-помощник         | История, подготовленные запросы, ожидание, ошибка и повтор с UUID. Карточки «Было → Станет» требуют выбора и отдельного подтверждения. Отмена изменённого плана также подтверждается.                                                                                                                                 |
| Настройки           | Аккаунт, тема, боковая панель, язык, часовой пояс, часы дня, напоминания и подключения. Есть несохранённое состояние, отмена, успешное сохранение и ошибка. Поля блокируются во время сохранения.                                                                                                                     |
| Подключения         | Статус OpenAI — «Ключ настроен», а не подтверждение доступности модели. Ключ вводится в закрытом поле и очищается при закрытии/успехе; в браузерное хранилище не записывается. Ключ из окружения сервера нельзя менять через заведомо неработающую кнопку. Google Calendar обозначен как запланированное подключение. |
| Доступность по коду | Нативные диалоги, подписи полей и кнопок, visible focus, состояния `aria-live`, мобильные области действий от 44 px, поддержка `prefers-reduced-motion`.                                                                                                                                                              |

## Исправления после обзора

- Выполнение повторяющейся задачи больше не завершает всю будущую серию.
- Ключи строк и показ времени используют календарный экземпляр, чтобы продолжение позднего события не получало дублирующийся React key или неправильное время.
- Истечение сессии обрабатывается в общей границе API, включая запросы из форм и чата.
- Во время отправки формы запрещены изменения, которые могли бы потеряться после ответа сервера.
- Форма объясняет ограничение текущего релиза: запись должна завершаться до полуночи. Утилита календаря умеет безопасно отображать переходящие записи, но форма их пока не создаёт.
- Удаление повторяющейся задачи явно спрашивает об удалении всей серии.
- Убрана несуществующая IANA-зона `Asia/Astana`; Астана относится к `Asia/Almaty`.
- У переключателей и флажков убраны конфликтующие глобальные `padding` и `min-height`; размер самого элемента согласован с его областью нажатия.
- Ограничения имени, API-ключа и модели согласованы с серверной валидацией. Ошибки подключения не подменяются сообщением об успешном подключении.

## Доказательства и границы

- `node --import tsx --test tests/calendar.test.ts`: **8 из 8 проходят**. Проверены даты до начала серии, недельные и месячные повторы, переход суток по часовому поясу, календарная арифметика, пересекающиеся события, выполнение отдельного экземпляра, поздние события, навигация по месяцам и задачи без времени.
- `npm run typecheck`: проходит после согласования клиентского и серверного `Task.completedDates`.
- Независимые серверные и HTTP-проверки описаны в `docs/security-review.md`.
- Полный интерфейс и работа на настоящем телефоне визуально не проверены: browser security policy отклонила localhost-вкладку, обход ограничения не выполнялся. Публичный экран входа после выпуска на Vercel отдельно отрисован во встроенном браузере; это не подтверждает остальные разделы и клавиатурные сценарии. Обзор CSS и доступности по исходникам не заменяет такую проверку.
- Настоящий OpenAI ещё не вызван с пользовательским ключом; модель и бюджет аккаунта не проверены. Google Calendar пока не подключён. Приложение использует одно персональное серверное пространство, а не независимые аккаунты нескольких пользователей.

Приложение опубликовано на Vercel, настройки production и облачные HTTP/API проверены; актуальные доказательства — в `docs/verification.md`. Остаются проверка реального отображения в разрешённом браузере, ввод пользовательского ключа и проверка настоящего ответа OpenAI. Ветка утверждённого дизайна сохранена; реализация объединена в main, темы и стили остаются частью исходников приложения.
