# Сервер Ritm

## Локальный запуск

Требуется Node.js 24+. Установите зависимости `npm install`, запустите
`npm run dev`. Сервер слушает `127.0.0.1:3001`, Vite — `127.0.0.1:5173` и
проксирует `/api`. Без ключа задачи, календарь и настройки работают; чат
показывает просьбу подключить OpenAI.

`.env` необязателен в локальном режиме. При необходимости скопируйте
`.env.example` в `.env`. Для пустого рабочего пространства задайте
`SEED_DEMO=false` перед первым запуском. Семь примеров создаются только при
первой инициализации SQLite относительно даты в `Asia/Qyzylorda`.

После `npm run build` команда `npm start` обслуживает `build/client` и API.
Чтобы использовать `NODE_ENV=production`, задайте `APP_PASSWORD` длиной
12–512 символов, даже если приложение слушает только локальный адрес.

## Данные и резервные копии

`data/ritm.sqlite` — задачи, локальные настройки и история диалогов одного
личного рабочего пространства. WAL и транзакции сохраняют подтверждённые
изменения. Серверной базы файлов и заметок нет. Удалённые задачи можно
восстановить из последних 50 удалений. Завершённые requestId чата сохраняются,
повторный запрос с тем же содержимым не оплачивает ещё одну генерацию.

Выполнение повторов хранится отдельно: `Task.completedDates` содержит даты,
а PATCH задачи с `{ completed, occurrenceDate }` меняет только выбранное
повторение. Обычная задача использует `completed`. Старые записи без массива
получают пустой массив при миграции версии 2; существующие задачи сохраняются.

Для резервной копии остановите сервер и скопируйте всю директорию `data/`.
Не копируйте только `ritm.sqlite` при запущенном сервере: актуальные данные
могут находиться в `ritm.sqlite-wal`. Для восстановления остановите сервер,
верните копию директории и запустите приложение.

Приложение рассчитано на один серверный процесс и одно личное пространство.
Для нескольких пользователей, нескольких реплик или serverless-размещения
потребуются отдельные аккаунты, общее хранилище сессий и другая база. Локальная
SQLite не подходит для эфемерных Vercel Functions.

## Подключение ИИ

OpenAI подключается серверным пакетом `@ai-sdk/openai`; по умолчанию используется
`gpt-6-luna`. Название модели можно изменить в настройках или `OPENAI_MODEL`.
Модель и поддержку Structured Outputs проверяли по официальным страницам:

- https://developers.openai.com/api/docs/models/gpt-6-luna
- https://developers.openai.com/api/docs/guides/structured-outputs

Ключ можно задать через `OPENAI_API_KEY` или сохранить в настройках. Вторая
форма использует AES-256-GCM: шифротекст в `data/openai-secret.json`, случайный
ключ шифрования в `data/.secret-key`. Директория игнорируется Git. Это защита
от случайного раскрытия в базе/исходниках; доступ к обоим файлам даёт доступ
к секрету, поэтому ограничьте права на `data/` средствами ОС. Резервируйте
оба файла вместе. `bootstrap` содержит только статус, источник и модель.

Переменная окружения имеет приоритет. Если ключ задан через окружение, API
честно сообщает источник `environment`, а изменение/удаление из UI возвращает
409: нужно изменить серверную переменную и перезапустить процесс. Сохранение
ключа проверяет формат, но не делает платный запрос и не подтверждает доступ
к конкретной модели. Реальный отказ OpenAI отображается при первом сообщении.

Помощник использует AI SDK 7 `ToolLoopAgent` и `Output.object`. Его инструкции
в `agent/instructions.md` отделены от предметной логики. Модель получает
снимок задач, часовой пояс, рабочие часы и последние 20 сообщений. При больших
списках контекст ограничен 300 ближайшими незавершёнными/завершёнными записями;
число включённых и общее число передаются модели явно. Лимит ответа — 3000
токенов, таймаут — 90 секунд, один повтор транспортного запроса.

Ответ модели не имеет инструментов изменения данных. Сервер повторно
проверяет ID, дату, время, длительность и тип записи. Карточки расписания
сохраняются со снимком версии задачи. Только API применения после выбора
пользователя меняет расписание, атомарно и с проверкой пересечений. Встречи,
завершённые и повторяющиеся задачи модель не перемещает. Отмена сверяет
версию после применения и не перезаписывает последующие ручные изменения.
При ошибке генерации ни пользовательский текст, ни частичный ответ не
добавляются в историю; повтор с тем же requestId разрешён.

Eve 0.77 рассмотрели по документации установленного пакета. Документированный
самостоятельный запуск требует компиляции `eve build`, отдельного Nitro
сервера, Workflow world и проксирования `/eve/` и
`/.well-known/workflow/`. Документированного встроенного запуска внутри
Express нет. Для текущего одного Express-процесса используется поддерживаемый
AI SDK агент; устойчивость истории обеспечивает SQLite. Установка Eve сама
по себе не означает, что здесь работает его durable runtime.

## Доступ и безопасность

По умолчанию приложение доступно только через loopback и не требует пароля.
Задайте `APP_PASSWORD`, чтобы получить вход по паролю и HttpOnly cookie на
8 часов. Сессии хранятся в памяти; перезапуск требует нового входа. Cookie:
SameSite=Strict, Secure при HTTPS `APP_ORIGIN`. Пароль сверяется scrypt и
constant-time сравнением; в браузер и SQLite он не передаётся.

Для сетевого доступа нужны одновременно `HOST`, `APP_PASSWORD` и
`APP_ORIGIN=https://...`. Терминацию HTTPS настройте обратным прокси. Без
пароля сервер отказывается запускаться на сетевом адресе. `trust proxy`
выключен; IP для лимитов берётся из сокета, а не пользовательского заголовка.
В простом обратном прокси лимит будет общим для клиентов — это ожидаемо для
одного личного пространства. HTTP origin допускается только для localhost.

API проверяет Host/Origin против конфигурации, запрещает cross-site запросы
и требует `Content-Type: application/json` для всех мутаций, включая DELETE
без тела. Лимиты: 120 мутаций/минуту, 10 запросов ИИ/минуту, 10 попыток
входа/15 минут на адрес. Вход, запросы с ошибками и `/api/session` не раскрывают
ключ. В production включается CSP. Секреты и сырые provider errors не
логируются. Запуск тестов не обращается к OpenAI: провайдер заменён локальным
контрактным runner только в тестовой фабрике.

Google Calendar ещё не подключён. Приложение использует локальные задачи;
типовая граница будущей интеграции описана в `shared/calendar-adapter.ts`.
Реализации адаптера, OAuth и синхронизации ещё нет; UI показывает этот статус.

## Бюджет контекста ИИ

Полный сериализованный ввод ограничен 64 000 символов, включая инструкции,
историю и текущий запрос. Текущий запрос сохраняется целиком; приоритет —
ближайшие незавершённые дела и фиксированные встречи. Передаются до 300 задач,
описания до 400 символов и последние 90 выполненных дат каждого повторения.
История ограничена 12 000 символов и 2 000 символов на сообщение. Контекст
явно сообщает о сокращениях; непоказанные данные не считаются отсутствующими
или невыполненными. Подробности — `docs/ai-review.md`.

## API

Общие типы — `shared/types.ts`. Ошибки: `{ error: string, code: string }` с
русским сообщением. Некорректные поля — 400, вход — 401, чужой origin — 403,
изменившийся план — 409, лимиты — 429, недоступный OpenAI — 502/503/504.

`GET /api/session`, `POST /api/login`, `POST /api/logout` управляют входом.
`GET /api/bootstrap` загружает всё пространство. CRUD задач, настроек и
диалогов находится под `/api/tasks`, `/api/settings`, `/api/conversations`.
`POST /api/chat` принимает `{ conversationId?, message, requestId }`.
`POST /api/proposals/apply|undo|reject` принимает
`{ conversationId, messageId, proposalIds }`. Apply и undo возвращают
`{ tasks, conversation }`; reject — обновлённый диалог.
