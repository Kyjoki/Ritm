# Независимая проверка ИИ и безопасности

Проверено 13 октября 2026 года: `server/`, `agent/instructions.md`, общие
контракты и серверные тесты. Проверки выполнялись под Node.js 24 без реальных
платных запросов OpenAI. Интерфейс браузером в этой проверке не проверялся.

## Исправление по результатам проверки

Ограничение в 300 задач не ограничивало размер входа модели: описания могли
занимать около 1,2 МБ, а история добавляла до 200 тысяч символов. Это создавало
риск лишних расходов и отказа модели из-за размера контекста.

`prepareAssistantInput` теперь ограничивает сериализованные инструкции,
сообщения истории и текущий запрос суммарно 64 тысячами символов. Проверяется
длина JSON после экранирования, а не только исходных строк. Текущий запрос
передаётся целиком. История ограничена 12 тысячами символов, одно прошлое
сообщение — двумя тысячами; короткие списки шагов сохраняются для уточняющих
вопросов. Ближайшие незавершённые задачи, встречи и актуальные повторения
попадают в контекст раньше далёких и завершённых дел.

Описания ограничены 400 символами, даты выполнения повторяющейся задачи —
последними 90 записями. Модель получает фактическое число включённых задач,
общее число задач и флаги сокращения истории/деталей; для повторов передаётся
полное количество выполненных дат. Инструкции требуют сообщать об ограничении
для плана и отчёта и не считать непоказанные повторения невыполненными.
Это ограничение размера входа; точную денежную стоимость оно не задаёт.

## Проверенные границы

- Модель не получает инструментов изменения данных, команд ОС и произвольных
  сетевых адресов. OpenAI использует фиксированный официальный endpoint.
- Структура ответа, идентификаторы задач, реальные даты, время, длительность,
  повторы и тип записи повторно проверяются сервером. Неизвестные действия и
  несколько изменений одной задачи отклоняются.
- Предложения сохраняются отдельно от задач. Применение и отмена выполняются
  транзакцией с проверкой версии и пересечений. Последующие ручные изменения
  не перезаписываются отменой.
- Незавершённый запрос блокирует повтор того же requestId, второй запрос
  в том же диалоге и удаление диалога. Одновременное подтверждение предыдущего
  предложения сохраняется при записи нового ответа.
- Секрет не входит в ответ bootstrap, SQLite и клиентскую сборку. Сохранённый
  ключ защищён AES-256-GCM; изменение шифротекста приводит к безопасной ошибке.
  Переменная окружения имеет приоритет и не требует расшифровки локального
  секрета.
- API проверяет Origin/Host, требует JSON для мутаций и защищает рабочее
  пространство сессией, если задан пароль. Внешний адрес и production требуют
  пароль, а публичный origin — HTTPS.
- Текст сообщений отображается React как текст, без HTML-интерпретатора.
  Данные задач и сообщения могут содержать недоверенные инструкции; инструкции
  агента явно определяют их как данные. Это не доказывает иммунитет модели
  к prompt injection, но ограничивает возможные действия проверенным API и
  явным подтверждением пользователя.

## Результаты тестов

В `tests/security.test.ts` добавлены пять проверок, все прошли:

1. Большой контекст с экранированными строками и 5000 датами повторений
   укладывается в бюджет, сохраняет текущий запрос и фиксированную встречу.
2. Короткие шаги из прошлого ответа доступны для уточняющего вопроса.
3. Дубли, неизвестные ID и посторонние действия модели отклоняются.
4. Изменение шифротекста обнаруживается, приоритет переменной окружения
   сохраняется, секрет можно безопасно настроить заново.
5. Конкурентный запрос блокирует дубли/удаление и сохраняет подтверждённое
   изменение предыдущего плана без повторной генерации завершённого запроса.

Основные проверки CRUD, сессий, происхождения запросов, восстановления,
устаревших планов, пересечений и повторов находятся в `tests/server.test.ts`.

## Практические ограничения

Это одно личное пространство и один серверный процесс с постоянной
директорией `data/`. Несколько реплик и эфемерные функции требуют другой
архитектуры хранения. Задачи и ключ следует резервировать при остановленном
сервере вместе со всей директорией, включая WAL и `.secret-key`.

Ключ шифрования лежит рядом с шифротекстом: доступ к обоим файлам раскрывает
секрет. На Windows права следует ограничивать средствами ОС; параметр mode
сам по себе не заменяет ACL. Серверный пароль и HTTPS обязательны для сетевого
размещения, доступ с телефона потребует такого размещения.

Idempotency предотвращает повторную генерацию уже сохранённого запроса в
сохранившемся диалоге. Остановка процесса во время вызова провайдера или
удаление диалога не дают гарантии единственной оплаты запроса. Сессии
находятся в памяти и сбрасываются при перезапуске.

Доступ к реальной модели, качество её ответов и стоимость проверяются после
подключения пользовательского ключа. Контрактные тесты не заменяют эту
проверку. Google Calendar пока не подключён; модель получает честный статус.
