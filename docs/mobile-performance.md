# Мобильная производительность Ritm — локальная проверка

Ветка `codex/mobile-performance`, отдельный worktree `mobile-performance/Ritm`, база `6254f737459c0968d6901a39785d07e618686bfc`. Main, GitHub и Vercel не изменялись. Серверный планировщик Telegram не изменялся.

## Подтверждённые причины и изменения

- Календарь создавал Intl.DateTimeFormat для каждой подписи временного слота; стабильный ограниченный cache форматтеров и подписи на день убирают сотни повторных конструкций. Массивы календарных задач/пустых событий стабильны; 42 дня месячной сетки не рассчитываются в неделе/дне.
- MotionList измерял и глубоко клонировал все строки при каждом рендере родителя. Теперь посторонние обновления пропускаются, копии неизменившихся строк переиспользуются, чтения геометрии выполняются перед записями; ширина и Activity корректно инвалидируют снимки.
- MotionControls реагировал на посторонние изменения всего приложения и перемежал чтения/записи. Теперь обновляются только затронутые группы, с пакетными измерениями и пропуском одинаковых значений.
- Каждый столбец графика обновлял React state и height на каждом кадре. Столбцы теперь используют WAAPI scaleY от текущего состояния. Числа/SVG имеют максимум 30 обновлений/с на мобильном и 60 на desktop; финальное значение точное. Анимации останавливаются при скрытии/смене reduced-motion; циклы сфер — также вне экрана.
- Мобильные контентные панели больше не создают отдельный backdrop blur; плотная поверхность сохраняет палитру. Blur нижней навигации уменьшен. Обратная связь кнопок, галочки, прогресс и переходы сохранены.
- Скрытые ещё не посещённые страницы не создаются заранее. Посещённые остаются внутри Activity, сохраняя формы и прокрутку. Часы обновляют React только при смене минуты; при скрытом документе работа прекращается, кроме уже разрешённых браузерных уведомлений. Возвращение/pageshow обновляет время.
- Убран GET после собственного успешного PATCH привычки. Чтения отменяются при скрытии и записи; запоздавшие ответы не заменяют новые данные. Отложенная сверка ждёт все параллельные записи и активную страницу. Создание до первого снимка данных обязательно дочитывает полный список.
- Аналитика привычек/финансов и streak мемоизированы. Изменения валюты/языка/часового пояса/суток сохраняют правильные результаты.
- Resize/scroll визуального viewport диалога объединяются в один RAF; одинаковые координаты не записываются повторно. Нативный dialog и блокировка фона сохранены.

## Методика

Production frontend Vite/React, Node 24.19.0. Локальный loopback сервер с временной SQLite и отдельными демонстрационными данными; серверный режим development нужен только для локального входа без пароля. Frontend собран именно в production, без Vite dev/HMR.

Windows Chromium (встроенный браузер Codex), эффективная область 390×844 CSS px, одинаковая тёмная тема и данные. CPU throttling не применялся. Время только тестового стенда закреплено на 27 октября 2026, чтобы полночь не меняла исходные списки. Ни один реальный календарь/аккаунт не используется: 28 Google-shaped событий синтетические; тестовый сервер показывает их и поддерживает локальное редактирование. Индикация Google в демо не подтверждает настоящее подключение.

Probe считает вызовы getBoundingClientRect/cloneNode, запросы, Long Tasks >50 мс, интервалы RAF и время от клика до двух последующих RAF. Это прокси отклика, **не** полное время React commit, INP или точный FPS GPU. Обёртки измерителя одинаковы для обеих сборок. Показания зависят от нагрузки Windows/GC; повторные прогоны показывали разброс.

Контрольный сценарий: после открытия «Моего дня» и одного захода в привычки — три цикла Привычки → Финансы → Календарь → ИИ → Настройки → Мой день (18 переходов).

| Метрика                           |     До |  После |
| --------------------------------- | -----: | -----: |
| Длительные JS-задачи              |     22 |      3 |
| P95 интервала RAF                 |  56 мс |  28 мс |
| Интервалы RAF >34 мс              |     93 |     23 |
| Вызовы чтения геометрии           |    575 |    306 |
| Глубокие копии DOM                |    184 |     63 |
| Запросы за сценарий               |     24 |     24 |
| Медиана клика в календарь → 2 RAF | 191 мс | 174 мс |

В предыдущем таком же прогоне медиана календаря была 240 → 142 мс; поэтому устойчивое преимущество подтверждается прежде всего сокращением работы и длинных задач, а не обещанием фиксированной скорости каждого клика.

Отдельно выполнение и отмена IELTS: 4 запроса → 2 (только записи, без двух лишних GET); длительных задач нет в обеих версиях. Смена Неделя/Месяц трижды: 6 → 0 длинных задач, чтения геометрии 121 → 81, копии 21 → 6.

Прокрутка заполненного календаря на компьютере была плавной в обеих версиях: длинных задач нет; P95 7 → 8 мс. Это не доказывает отсутствие GPU-проблем на iPhone.

Стресс-данные: 100 дополнительных задач и 80 сообщений. Прокрутка каждого списка не дала Long Tasks в проверенном окружении (P95 RAF 7 мс). Виртуализация пока не добавлялась: замер не подтвердил её необходимость, а она потребовала бы дополнительной проверки фокуса/поиска/прокрутки. После трёх серий повторных переходов между этими страницами DOM оставался 1591 элемент, heap 15/14/17 МБ. В обычном сценарии heap колебался вплоть до 30 МБ до GC; уменьшение памяти не заявляется. Короткая серия и performance.memory не заменяют heap snapshots/длительный leak test.

Исходные измерения: `test-results/mobile-performance/final-navigation.json`, `filled-calendar.json`, `comparison.json`, `stress.json`, `memory.json`.

## Проверки

- Typecheck, production build, Prettier и git diff --check прошли.
- **266 тестов прошли**, в том числе 12 новых: устаревшие ответы, параллельные записи, скрытие/reconnect, первый снимок, locale/timezone/currency и геометрия/cleanup диалогов.
- В браузере: все разделы; habit completion/undo; week/month аналитика; день/неделя/месяц календаря; просмотр/редактирование события; новый habit-dialog; Escape; светлая/тёмная темы; мобильные 360/390/430 и альбомные 844×390; desktop около 1440×900.
- Центрирование и блокировка фона подтверждены. Keyboard viewport event bursts проверены unit-тестом; настоящая экранная клавиатура iOS не проверялась.
- Черновики быстрой задачи и сообщения сохранились после переходов. Прокрутка календаря до/после возврата: 722.727 px в обоих случаях.
- Native mouse-drag в доступном инструменте не дал подтверждённого переноса; не считаем его успешным E2E-тестом. Алгоритмические тесты календаря/переноса прошли. Touch long-press и свайпы требуют реального устройства.
- Встроенный браузер держит document.hidden=false даже для фоновых тестовых вкладок. Реальное сворачивание iOS, bfcache и installed web-app lifecycle здесь не воспроизводились. Cleanup и очереди скрытой Activity проверены кодом/тестами и переходами.
- Изображения/зависимости не добавлялись. JS bundle около 602 KB (gzip около 173 KB); предупреждение Vite о chunk >500 KB остаётся. Оно не подавлено. Разделение загрузки кода — отдельный потенциальный этап, если холодный старт на устройстве подтвердит проблему.

## Локальный просмотр

- Оптимизированная версия: http://127.0.0.1:4181/#day
- Сохранённая исходная сборка: http://127.0.0.1:4180/#day
- Стресс-стенд запускается отдельно на 4182.

Запуск из нового worktree под Node 24:

```powershell
node --import tsx scripts/performance/serve.ts after
# Сохранённая база не пересобирается из изменённого кода:
node --import tsx scripts/performance/serve.ts before --no-build
node --import tsx scripts/performance/serve.ts stress --no-build
```

Каждый запуск создаёт новые временные демоданные; изменения в них не попадают в production. Все процессы слушают только 127.0.0.1. Ни секреты, ни проектные .env не загружаются. Probe и фиксированная дата подключаются только локальным runner и не входят в обычную сборку приложения.

Локальный адрес на компьютере недоступен напрямую с iPhone. Проверка настоящего Safari и «На экран Домой» остаётся обязательным отдельным шагом до заявления о готовности именно для iPhone. На этапе локальной оптимизации публикация не выполнялась. Позднее владелец отдельно разрешил production-выпуск после проверок; реальный iPhone этим разрешением не считается протестированным.

## Дополнение перед выпуском: переводы в финансах

По последующему разрешению владельца подготовлен общий выпуск оптимизации и ручных переводов. Финальная проверка: 270 тестов проходят под Node 24 с `--throw-deprecation`, production build/typecheck, Prettier, diff --check и npm audit (0 уязвимостей). В браузере локальной production-сборки проверены пополнение, снятие, исправление суммы, сохранность после перезагрузки, перевод между депозитами и неизменность сумм доходов/расходов. Удаление и восстановление расчётных остатков проверены API/SQLite/Postgres-тестами; PostgreSQL здесь эмулирован pg-mem, отдельный конкурентный тест реальной production-базы не проводился.

Форма переводов проверена в обеих темах, при ширинах 360/390/430 px и на desktop: горизонтального overflow нет, диалог ограничен доступной высотой, действия доступны, минимальная высота мобильных кнопок 44 px. Дополнительный review исправил недостающие ARIA-даты в месячном календаре; все 42 дня имеют корректные подписи. Ошибок консоли в проверенных сценариях нет. Настоящий iPhone 13 / iOS 17.6.1 остаётся непроверенным устройством.
