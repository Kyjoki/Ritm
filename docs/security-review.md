# Проверка безопасности Ritm

Дата: 13 октября 2026 года. Проверена реализация `server/**`, `agent/**`, граница клиентского API и интерфейс подтверждения предложений ИИ. Это обзор текущего персонального приложения; отдельная проверка публичного развёртывания требуется после выбора хостинга.

## Что выполнено

- На первом этапе тесты Node.js 24.19.0: **16 из 16 проходят** — `tests/server.test.ts` и `tests/calendar.test.ts`. Второй независимый обзор добавил 5 проверок в `tests/security.test.ts`; итог всего набора указан в `docs/verification.md`.
- Дополнительно выполнены **10 независимых HTTP-проверок** настоящих маршрутов Express с временной SQLite-базой и тестовым `AssistantRunner`.
- `npm run typecheck` проходит.
- Настоящие ключи не использовались, запросов к OpenAI не было. Внешние ответы в тестах заменены явно заданным mock; это не подтверждает доступность модели или действительность пользовательского API-ключа.

Независимые HTTP-проверки: закрытый `/bootstrap` без сессии; вход и атрибуты cookie; отсутствие ключа в bootstrap; запрет чужого Origin; запрет мутации с `text/plain`; запрет чужого Host; повтор запроса с одинаковым UUID без повторного вызова модели; конфликт при подмене сообщения для того же UUID; отказ на неизвестный taskId без сохранения диалога; удаление диалога без тела запроса.

Готовые серверные тесты дополнительно проверяют шифрование сохранённого ключа, отсутствие ключа в SQLite, logout, отключение ИИ, обязательность пароля при публичном/production запуске, запрет публичного HTTP origin, режим ключа из environment, CRUD и восстановление задач, сохранность данных после открытия новой Store, повторение задач, отклонение некорректного ответа ИИ, атомарное применение выбранных изменений, stale/collision rollback и безопасную отмену после ручного редактирования.

## Проверенные границы

| Граница                      | Реализация и подтверждение                                                                                                                                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Доступ к персональным данным | При настроенном пароле защищённые API требуют серверную сессию. Production или bind вне loopback без пароля прекращает запуск. Cookie имеет `HttpOnly`, `SameSite=Strict`, срок 8 часов; `Secure` включается для HTTPS `APP_ORIGIN`.                              |
| Межсайтовые запросы          | API проверяет Host, разрешённый Origin, `Sec-Fetch-Site` и JSON Content-Type для мутаций. Dev-сервер привязан к `127.0.0.1`; доверие произвольным proxy-заголовкам отключено.                                                                                     |
| Ключ OpenAI                  | Передаётся серверу, отсутствует в bootstrap и ответах настройки. Сохранённый ключ находится в AES-GCM-конверте вне SQLite. В репозитории игнорируются `/data/`, `.env`, SQLite и служебные файлы.                                                                 |
| Ответ модели                 | Structured output проходит серверные ограничения формы, даты, времени, длительности и идентификаторов задач. Отсекаются выполненные задачи, встречи, повторяющиеся серии, повторные taskId, прошлое время и предложения без изменения.                            |
| Изменения расписания         | Модель не получает инструментов записи. Пользователь выбирает карточки и отдельно подтверждает применение. API применяет только переданные proposalIds в SQLite-транзакции. Проверяются версия задачи, исходное расписание, текущее время и пересечения.          |
| Отмена                       | Возвращает только выбранные применённые изменения. Ручное редактирование после применения делает старую отмену недопустимой. Ошибка не оставляет частично изменённые задачи.                                                                                      |
| Повтор чата                  | Устойчивый UUID и fingerprint запроса хранятся сервером. Повтор завершённого запроса возвращает существующий диалог без второго вызова модели. Ошибка провайдера не создаёт ложные сообщения и допускает повтор.                                                  |
| Внешний ввод                 | Модель не имеет средств обращения к пользовательским URL или ОС; адрес OpenAI фиксирован. Тексты чата, задач, шагов и причин выводятся React как обычный текст. HTML модели не исполняется. Ошибки провайдера не возвращают его raw payload, заголовки или stack. |

## Найдено и исправлено во время обзора

1. Клиентские мутации без тела не передавали JSON Content-Type. После изменения клиента обнаружено, что Express `req.is()` также не распознаёт Content-Type у запроса без тела. Защита теперь проверяет сам заголовок: DELETE и logout работают при сохранении JSON-барьера.
2. Проверка loopback не учитывала `[::1]` из `URL.hostname`. IPv6-вариант добавлен.
3. `process.loadEnvFile()` при отсутствии `.env` останавливал запуск. Добавлена проверка существования файла.
4. ИИ мог вернуть корректное по форме время в прошлом или предложение без изменения. Добавлены семантические проверки; время повторно проверяется при применении плана.
5. Сохранение ключа не подтверждает реальный доступ к OpenAI. Статус интерфейса изменён на «Ключ настроен»; Google Calendar честно обозначен как неподключённый.
6. Папка данных и файлов шифрования добавлена в `.gitignore` до коммита.

## Ограничения проверки и эксплуатации

- Браузерная проверка и визуальная проверка работающего приложения не выполнены: browser security policy отклонила localhost-вкладку. Обход ограничений и Playwright-запуск не выполнялись. API-тесты запускались с разрешённым доступом к loopback.
- Публичное развёртывание, сертификат HTTPS, настройки reverse proxy, его ограничения запросов и резервное восстановление здесь не проверены. Для публикации нужны отдельная проверка окружения и сильный `APP_PASSWORD`.
- Приложение рассчитано на одно личное пространство и один серверный процесс. Несколько независимых пользователей, кластер серверов и распределённые сессии не реализованы.
- Ключ шифрования лежит рядом с зашифрованным секретом. Человек с доступом ко всей папке `data` может расшифровать сохранённый API-ключ. Защищайте папку и резервные копии средствами ОС; POSIX mode `0600` не является гарантией NTFS ACL на Windows.
- Настоящий OpenAI и Google Calendar не проверялись и не объявляются подключёнными. Ограничения запросов и output tokens заданы на сервере, но реальные расходы и лимиты аккаунта требуют настройки у провайдера.
- UI и accessibility проверены по исходникам. Проверка экранным диктором, клавиатурой в браузере, реальными мобильными экранами и пользовательскими данными остаётся для следующего разрешённого этапа.

После исправлений блокирующих замечаний в рассмотренной границе API/ИИ не осталось. Этот результат относится к выполненным проверкам и не означает, что публичное окружение уже готово или что найдены все возможные уязвимости.
