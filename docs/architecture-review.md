# Архитектурная проверка Ritm

Дополнение этапа подготовки Vercel: добавлены PostgreSQL, постоянные сессии, Google OAuth/Calendar и отдельный API handler. Актуальная облачная схема и оставшиеся проверки описаны в [инструкции Vercel](vercel.md). Ниже сохранён обзор первоначального локального варианта.

Проверка выполнена 13 октября 2026 года по исходникам приложения и короткому
изолированному запуску production API. Настоящие OpenAI и Google Calendar
не вызывались. Браузерная проверка на этой машине заблокирована политикой
доступа; HTTP-проверка не подтверждает визуальное поведение экранов.

## Состав приложения

- React и Vite собирают интерфейс в `build/client`.
- Express обслуживает API и готовую клиентскую сборку одним процессом.
- SQLite хранит задачи, настройки и историю одного личного пространства.
- Общие типы находятся в `shared/types.ts`; сервер повторно проверяет данные
  схемами Zod. Типы браузера не заменяют серверную валидацию.
- Ключ OpenAI задаётся окружением либо сохраняется сервером с AES-256-GCM.
  В `bootstrap` передаются только наличие ключа, источник и модель.
- AI SDK получает снимок задач и историю, а изменения применяет отдельный
  API после подтверждения пользователя. Версии задач и транзакции защищают
  применение и отмену предложений от устаревших данных.

Интерфейс и сервер согласованы по CRUD задач, выполнению отдельной даты
повторения, настройкам, истории диалогов и действиям над предложениями ИИ.
Сохранение API-ключа означает сохранённую конфигурацию; доступ к модели
проверяется только при настоящем сообщении пользователя.

## Запуск и окружение

Для эксплуатации нужен Node.js 24+. `.nvmrc` содержит `24`, а dev launcher
запускает оба дочерних процесса через `process.execPath`, поэтому сохраняет
версию родительского Node. `tsx` находится в production dependencies:
команда запуска TypeScript-сервера работает после `npm ci --omit=dev`.

На проверенной машине системный Node имеет версию 22.16.0, а bundled runtime
Codex — 24.19.0. Вызов установленного `npm.cmd` может использовать Node из
его собственного каталога. Изменение одного `PATH` не гарантирует смену
версии npm. Для воспроизводимого запуска следует переключить установленный
Node на 24 либо явно запустить bundled Node; автоматическая установка
runtime не выполнялась.

Локальная цепочка: зависимости → `npm run dev` → Vite `127.0.0.1:5173` →
прокси API `127.0.0.1:3001` → SQLite. Production цепочка: зависимости →
`npm run build` → `npm start` → Express → клиентская сборка и API.

Docker собирает клиент в отдельной стадии, устанавливает production
dependencies и запускает сервер от пользователя `node`. `/app/data`
выделен в volume. В production нужны пароль приложения и конфигурация
разрешённого HTTPS origin. Контейнер должен передавать SIGTERM непосредственно
Node; прямой `CMD` с Node предпочтителен запуску через npm.

## Компьютер и телефон

Оба устройства могут работать с одной серверной базой, если открывают один
и тот же доступный HTTPS-адрес приложения. Это одно личное пространство
с общим паролем; отдельные учётные записи не реализованы. Локальный адрес
`127.0.0.1` предназначен для компьютера, на котором запущен сервер.

Приложение читает `bootstrap` при открытии и перезагрузке. Свои успешные
изменения интерфейс получает из ответа API. Постоянного канала WebSocket,
автоматического получения изменений другого устройства и автономного
режима с последующей синхронизацией сейчас нет. После работы на другом
устройстве обновите страницу, чтобы получить актуальный список.

Серверная база файлов и заметок отсутствует. Google Calendar не подключён;
его интеграция остаётся отдельным этапом пользователя.

## Долговечность данных

SQLite использует WAL, busy timeout и транзакции. Каталог `data/` содержит
базу, журнал и серверное хранилище ключа OpenAI; он исключён из Git и
Docker build context. Для Docker необходимо сохранять volume между
пересозданиями контейнера. Для копирования остановленного приложения
резервируется весь `data/`, включая `.secret-key`, а не только файл базы.

Эксплуатация рассчитана на один серверный процесс. Сессии и лимиты
запросов находятся в памяти, поэтому перезапуск требует повторного входа.
Выполненные запросы чата, задачи и история сохраняются в SQLite. Несколько
реплик и эфемерные serverless-функции требуют другой архитектуры хранилища.

## Проверенные результаты

Изолированный HTTP runner использовал Node 24.19.0, `NODE_ENV=production`,
временный пустой `dataDir` и отдельный пароль проверки. Он подтвердил:

| Проверка                             | Результат                     |
| ------------------------------------ | ----------------------------- |
| HTML готовой сборки                  | HTTP 200                      |
| JS и CSS Vite                        | HTTP 200, непустое содержимое |
| Production CSP                       | Заголовок присутствует        |
| `bootstrap` до входа                 | HTTP 401                      |
| Вход по паролю                       | HTTP 200                      |
| Создание задачи                      | HTTP 201                      |
| Закрытие и повторное открытие SQLite | Созданная задача сохранилась  |

Runner закрыл слушающий порт и удалил только свой проверенный временный
каталог. Действующие пользовательские данные не менялись.

## Ветки и изменение дизайна

`codex/ritm-design` сохраняет утверждённый визуальный ориентир;
`codex/ritm-app` содержит реализацию, созданную от этой основы. После
объединения приложения новые изменения дизайна следует делать в отдельных
ветках от актуальной основной ветки. Постоянно расходящаяся ветка дизайна
не должна становиться вторым самостоятельным приложением. Цветовые токены,
стили и компоненты остаются отдельно от серверной логики и данных.
