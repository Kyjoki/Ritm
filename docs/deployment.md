# Запуск сервера Ritm

## Обычный сервер

Для Vercel используйте [отдельную инструкцию](vercel.md): статический интерфейс, API Function и PostgreSQL. Ritm опубликован на https://ritm-eta-hazel.vercel.app; облачные HTTP/API-проверки описаны в [отчёте выпуска](verification.md). Ниже описан отдельный вариант локального сервера и Docker.

Локальный сервер требует Node.js 24, постоянный диск и один процесс при SQLite. SQLite, ключи и история находятся в `DATA_DIR` (по умолчанию `data/`). Для размещения с SQLite нужен Node-сервер или контейнер с томом.

1. Установите зависимости: `npm ci`.
2. Соберите интерфейс: `npm run build`.
3. Настройте окружение из `.env.example`.
4. Запустите `npm start` под менеджером процессов.
5. Настройте HTTPS reverse proxy на порт 3001.

Для сетевого размещения обязательны:

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=3001
APP_ORIGIN=https://ritm.example.com
APP_LOGIN=<логин владельца>
APP_PASSWORD=<случайный пароль длиной от 12 символов>
APP_SESSION_SECRET=<случайный постоянный секрет длиной от 32 байт>
DATA_DIR=/persistent/ritm
```

Подставьте свой адрес и пароль. `APP_ORIGIN` содержит только схему и домен, без пути. Публичный адрес требует HTTPS. Пароль даёт доступ ко всему личному пространству. Не размещайте общий экземпляр для разных пользователей.

Reverse proxy передаёт исходный `Host` и `Origin`. Приложение не доверяет пользовательским `X-Forwarded-*`. Cookie защищена `HttpOnly`, `SameSite=Strict` и `Secure` при HTTPS origin. Восьмичасовая сессия сохраняется между перезапусками при сохранении runtime-базы и ключей. Для Google callback используется отдельная одноразовая correlation cookie с `SameSite=Lax`.

## Docker

```sh
docker build -t ritm .
docker run --rm --name ritm -p 127.0.0.1:3001:3001 --env-file .env.production -v ritm-data:/app/data ritm
```

Создайте `.env.production` с `APP_ORIGIN`, `APP_LOGIN`, `APP_PASSWORD`, `APP_SESSION_SECRET` и при необходимости `OPENAI_API_KEY` / `OPENAI_MODEL`. Контейнер задаёт production, host, port и путь данных. Настройте HTTPS proxy на локальный порт.

Dockerfile подготовлен; для сборки нужен установленный Docker. В этой сессии проверены TypeScript, Vite и API-тесты, контейнер не запускался.

## Подключение телефона

Откройте защищённый адрес сервера и войдите с тем же логином и паролем. Общее состояние хранится на сервере. Изменения с другого устройства появляются после обновления страницы; live-синхронизация пока не реализована.

## Эксплуатация

- Один экземпляр на один `DATA_DIR`; не подключайте общий SQLite к нескольким контейнерам.
- Сохраняйте том при обновлении и делайте закрытые резервные копии после остановки процесса.
- `GET /api/health` проверяет доступность процесса. Полный сценарий проверяется авторизованным запросом API.
- Установите бюджет OpenAI в своём аккаунте. Сервер ограничивает частоту чата, но не ведёт биллинг токенов.
- При обновлении выполните `npm ci`, `npm run build`, `npm test`, затем перезапустите сервер.
- Публичная эксплуатация требует TLS, резервных копий и защиты сервера.
