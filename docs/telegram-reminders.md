# Автоматические напоминания Telegram

Ritm проверяет расписание через серверный `POST /api/integrations/telegram/reminders/run`. Браузер для отправки не нужен. Проверка запускается внешним QStash Schedule каждые две минуты; Vercel Hobby не поддерживает такую частоту встроенного cron.

## Подключение production

1. Создайте QStash в Upstash на тарифе Free. Одна проверка каждые две минуты требует 720 доставок в день при лимите 1000. Скрипт отключает повторы QStash, чтобы ошибки endpoint не увеличивали число вызовов; следующий плановый запуск повторно проверит пятиминутное окно. Следите за общим использованием QStash, если в аккаунте есть другие расписания.
2. Привяжите существующий QStash к проекту Ritm в Vercel для Production как Sensitive. Он добавит `QSTASH_CURRENT_SIGNING_KEY` и `QSTASH_NEXT_SIGNING_KEY`. После добавления переменных выполните новый deployment. Endpoint проверяет подпись QStash, точный адрес и хеш исходного тела запроса. Дополнительный `REMINDER_SCHEDULER_SECRET` длиной от 32 символов остаётся запасным способом авторизации; храните его только на сервере.
3. В приватном локальном окружении укажите `APP_ORIGIN=https://ritm-eta-hazel.vercel.app`, `QSTASH_URL` (REST API URL из панели Upstash) и `QSTASH_TOKEN`. Запустите `node scripts/configure-telegram-reminders.mjs`. Скрипт создаёт/обновляет стабильный schedule `ritm-telegram-reminders` с `*/2 * * * *`, POST JSON `{}` и без повторов QStash. Если задан дополнительный секрет, он передаётся закрытым заголовком. Расписание можно создать с теми же параметрами в панели Upstash.
4. В настройках Ritm проверьте привязанный личный чат и Google Calendar, выберите опережение и включите напоминания. Тестовая кнопка проверяет только Telegram. После первого успешного автоматического запуска (обычно в пределах двух минут плюс время обработки) статус перейдёт в «работает». Если запусков нет более пяти минут, статус снова покажет ожидание.
5. Для сквозной проверки создайте событие Google на 10–15 минут вперёд, закройте сайт и дождитесь сообщения. Затем отдельно проверьте перенос/удаление и выполненную задачу.

API проверяет подпись QStash текущим и следующим ключом либо дополнительный секрет постоянным по времени сравнением. Уведомления и курсор имеют устойчивые ключи в PostgreSQL (`ritm_server_secrets`, `ritm_leases`); дополнительная миграция не нужна. Один запуск берёт общую аренду, а каждая отправка — аренду уникального ключа. Запись `uncertain` сохраняется до сетевого вызова Telegram, поэтому при таймауте или аварии нет автоматического повтора с риском дубля. Такой выбор может пропустить одно сообщение, но не обещает невозможную гарантию одновременного отсутствия потерь и дублей. Явные 429/5xx Telegram повторяются ограниченно в рамках вызова; QStash сам запрос не повторяет ради соблюдения бесплатного лимита. Курсор и пятиминутное окно позволяют следующему двухминутному запуску обработать небольшую задержку; уведомления старше пяти минут не догоняются. При предупреждении за 30 минут обычный разброс из-за расписания — до двух минут; также возможны задержки Google, Telegram и serverless.

Google читается каждый запуск с раскрытием конкретных повторяющихся экземпляров. События без времени и завершённые Google Tasks пропускаются. Локальные задачи без времени или выполненные тоже пропускаются. Если Google вернул неполный результат или ошибку, курсор не продвигается и QStash может повторить вызов. Отключение или отвязка чата прекращает будущие отправки.

Не запускайте schedule до проверки production deployment и переменных. Не отмечайте функцию как активную только по успешному тестовому сообщению.

Документация тарифов: https://vercel.com/docs/cron-jobs/usage-and-pricing, https://upstash.com/pricing/qstash, https://upstash.com/docs/qstash/api-reference/schedules/create-a-schedule.
