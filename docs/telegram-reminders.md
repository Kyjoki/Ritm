# Автоматические напоминания Telegram

Ritm проверяет расписание через серверный `POST /api/integrations/telegram/reminders/run`. Браузер для отправки не нужен. Проверка запускается внешним QStash Schedule каждую минуту; Vercel Hobby не поддерживает такую частоту встроенного cron.

## Подключение production

1. Создайте QStash в Upstash с тарифом Pay as You Go. Free даёт 1000 сообщений в день, а одна проверка в минуту требует 1440 в день. При цене $1 за 100 000 доставок ориентир — около $0.43 в месяц за 30 дней без повторов и дополнительных расходов платформы.
2. Создайте случайный секрет не короче 32 символов. Задайте `REMINDER_SCHEDULER_SECRET` только в серверном окружении Vercel Production для проекта Ritm. После добавления переменной выполните новый deployment. Секрет не помещайте в репозиторий, браузер или командную строку как аргумент.
3. В приватном локальном окружении укажите `APP_ORIGIN=https://ritm-eta-hazel.vercel.app`, `QSTASH_URL` (REST API URL из панели Upstash), `QSTASH_TOKEN` и тот же `REMINDER_SCHEDULER_SECRET`. Запустите `node scripts/configure-telegram-reminders.mjs`. Скрипт создаёт/обновляет стабильный schedule `ritm-telegram-reminders` с `* * * * *`, POST JSON `{}`, двумя повторами запроса и закрытым заголовком авторизации.
4. В настройках Ritm проверьте привязанный личный чат и Google Calendar, выберите опережение и включите напоминания. Тестовая кнопка проверяет только Telegram. После первого успешного автоматического запуска (обычно до двух минут) статус перейдёт в «работает». Если запусков нет более пяти минут, статус снова покажет ожидание.
5. Для сквозной проверки создайте событие Google на 10–15 минут вперёд, закройте сайт и дождитесь сообщения. Затем отдельно проверьте перенос/удаление и выполненную задачу.

API проверяет секрет постоянным по времени сравнением. Уведомления и курсор имеют устойчивые ключи в PostgreSQL (`ritm_server_secrets`, `ritm_leases`); дополнительная миграция не нужна. Один запуск берёт общую аренду, а каждая отправка — аренду уникального ключа. Запись `uncertain` сохраняется до сетевого вызова Telegram, поэтому при таймауте или аварии нет автоматического повтора с риском дубля. Такой выбор может пропустить одно сообщение, но не обещает невозможную гарантию одновременного отсутствия потерь и дублей. Явные 429/5xx Telegram повторяются ограниченно в рамках вызова; QStash повторяет ошибочный вызов endpoint не более двух раз. Курсор и пятиминутное окно позволяют пережить небольшой сдвиг расписания; уведомления старше пяти минут не догоняются. Точность зависит от фактического запуска QStash, времени ответа Google и Telegram, а также задержек serverless.

Google читается каждый запуск с раскрытием конкретных повторяющихся экземпляров. События без времени и завершённые Google Tasks пропускаются. Локальные задачи без времени или выполненные тоже пропускаются. Если Google вернул неполный результат или ошибку, курсор не продвигается и QStash может повторить вызов. Отключение или отвязка чата прекращает будущие отправки.

Не запускайте schedule до проверки production deployment и переменных. Не отмечайте функцию как активную только по успешному тестовому сообщению.

Документация тарифов: https://vercel.com/docs/cron-jobs/usage-and-pricing, https://upstash.com/pricing/qstash, https://upstash.com/docs/qstash/api-reference/schedules/create-a-schedule.
