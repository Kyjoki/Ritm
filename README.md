# Ritm

Личное пространство для задач, расписания и общения с ИИ. Русский интерфейс, фиолетовая палитра, светлая и тёмная темы, отдельная мобильная навигация.

## Возможности

- **Мой день** — задачи, прогресс, ближайшее событие, расписание, просроченные дела и задачи без даты.
- **Календарь** — день, неделя и месяц; на телефоне по умолчанию повестка дня. Свободный интервал открывает создание записи.
- **Задачи** — создание, изменение, приоритет, длительность, повторение и отмена удаления. Выполнение повторов хранится отдельно для каждой даты. Редактирование и удаление повторяющейся задачи относятся ко всей серии.
- **ИИ-помощник** — настоящий серверный OpenAI API, история диалогов, планы, шаги и отчёты. Переносы показываются карточками «Было → Станет» и применяются после выбора и подтверждения. Отмена и применение проверяют актуальность задач и пересечения.
- **Настройки** — профиль, оформление, рабочие часы, часовой пояс, уведомления и серверное подключение OpenAI.

Задачи, настройки и история сохраняются в SQLite. Google Calendar показывает статус «Не подключён»: его интеграцию пользователь реализует отдельно. Разделов файлов и заметок нет.

## Быстрый запуск

Нужны **Node.js 24+** и npm. Версия записана в `.nvmrc`.

```sh
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173**. API работает на порту 3001. При первом запуске создаются примерные задачи относительно сегодняшнего дня; их можно редактировать и удалять. Для пустого нового экземпляра задайте `SEED_DEMO=false` до первого запуска.

На этом компьютере системный Node имеет версию 22. Перед обычными npm-командами переключите его на 24. Уже установленный в Codex Node24 можно использовать для запуска без изменения системы:

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" scripts/dev.mjs
```

Эта команда подходит после установки зависимостей; они уже установлены в текущем checkout. Само изменение `PATH` может не переключить Node внутри Windows `npm.cmd`.

Готовая сборка:

```sh
npm run build
npm start
```

Адрес: **http://127.0.0.1:3001**. По умолчанию сервер доступен только с этого компьютера. Для доступа с телефона нужен общий сервер и защищённый адрес: [развёртывание](docs/deployment.md).

## OpenAI

В «Настройки → Подключения → OpenAI» сохраните ключ и название модели. Ключ передаётся серверу, шифруется и не попадает в ответы API, браузерное хранилище или репозиторий. «Ключ настроен» означает сохранённую конфигурацию; доступ к модели проверится при первом запросе.

Можно также скопировать `.env.example` в `.env` и задать `OPENAI_API_KEY` / `OPENAI_MODEL`. Серверный ключ имеет приоритет; изменять его нужно в окружении с перезапуском сервера. Запросы оплачиваются по условиям вашего API-аккаунта. Автотесты используют замену провайдера и не выполняют платных запросов.

ИИ получает задачи, рабочие часы, часовой пояс и последние сообщения выбранного диалога. Фиксированные события и повторяющиеся серии автоматически переносить нельзя. Для обычных задач доступны предложения переноса с подтверждением.

## Данные и доступ

`data/` создаётся локально и исключена из Git. Она содержит `ritm.sqlite`, журнал SQLite и, при сохранении ключа через интерфейс, `openai-secret.json` и `.secret-key`. Доступ ко всей папке позволяет расшифровать ключ. На Windows права `0600` не заменяют настройки NTFS — храните папку в защищённом профиле пользователя. Для сервера предпочтительна `OPENAI_API_KEY`.

Это **одно личное пространство** с логином и паролем владельца, без регистрации. Локально пароль необязателен; для production и сетевого доступа обязательны `APP_LOGIN`, `APP_PASSWORD` и постоянный `APP_SESSION_SECRET`. Сессия действует 8 часов, сохраняется между перезапусками и отзывается при выходе. Смена данных входа завершает прежние сессии.

## Google Calendar и Vercel

В настройках появилось подключение Google Calendar. Оно требует серверных `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` и согласия владельца. Старый Web OAuth-клиент можно использовать с дополнительным точным redirect URI; настройки другого приложения нужно сохранить. Секреты не отправляйте в чат. Подробности: [Google Calendar](docs/google-calendar.md).

После подключения основной календарь Google отображается вместе с задачами. Новые записи можно сохранять в Ritm или Google; события Google редактируются с проверкой версии. Записи с гостями, повторяющиеся и сложные события доступны для просмотра. Отключение удаляет подключение только из Ritm. ИИ учитывает занятость Google при планировании и подтверждении переносов задач.

Для Vercel подготовлены `vercel.json`, Vite-сборка `build/client`, `api/index.ts` и PostgreSQL. Файловая SQLite остаётся для локального сервера. Проект Vercel, настоящая облачная база и Google credentials пока не подключены. [Порядок настройки и проверки](docs/vercel.md). Production-публикация отложена: пользователь хочет выполнить дополнительную задачу перед запуском.

Напоминания работают при открытом Ritm после разрешения браузера: за 15 минут до дела и в начале рабочего дня. Фоновые push-уведомления и письма не подключены.

Для резервной копии остановите приложение и скопируйте всю папку `data/` в закрытое хранилище. Для восстановления остановите приложение, верните копию и запустите сервер. Сохраните `.secret-key` вместе с зашифрованным ключом.

## Проверки

```sh
npm run build
npm test
npm run format:check
```

90 тестов проверяют SQLite/API, постоянные сессии, шифрование, повторную отправку чата, подтверждение и отмену предложений, повторы, Google OAuth и события с заменой провайдера, часовые пояса и PostgreSQL-контракты через pg-mem. Дополнительные проверки безопасности покрывают Host/CSRF/cookie, квоты, ограничение HTTP, журнал, параллельность ИИ, размер данных, allowlist исходящих запросов и строгий AES-GCM. Реальные Google и PostgreSQL проверяются после настройки credentials. Отчёты: [проверки](docs/verification.md), [безопасность](docs/security-review.md), [обзор команды](docs/implementation-review.md).

## Дизайн и ветки

Макеты сохранены в `design/approved-preview.html` и ветке **`codex/ritm-design`**. Реализация — **`codex/ritm-app`**. Цвета находятся в `src/styles/tokens.css`; интерфейс отделён от API и базы.

После слияния приложения в `main` создавайте новую ветку дизайна **от свежей `main`**, например `codex/design-refresh`. Меняйте токены и компоненты, проверяйте результат и сливайте через PR. Так обновлённый дизайн сохранит актуальную логику.
