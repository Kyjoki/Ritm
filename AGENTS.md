# Инструкции для команды Ritm

Дизайн утверждён пользователем 13 октября 2026 года. Пользователь разрешил полноценную реализацию и автономную работу команды. Основа интерфейса — фиолетовые светлая и тёмная темы из `design/approved-preview.html`. Поддерживайте разделы «Мой день», «Календарь», «ИИ-помощник», «Финансы», «Настройки». Раздел «Финансы» добавлен по прямому запросу владельца 14 октября. Не добавляйте разделы файлов и заметок.

Читайте `docs/product-brief.md` и `docs/decisions.md` перед началом задачи. Используйте зоны ответственности из `docs/team.md`. Не помещайте API-ключи и другие секреты в репозиторий или браузерный код. Не добавляйте серверную базу для файлов и заметок до отдельного решения пользователя.

Темы и визуальные токены держите отдельно от предметной логики. ИИ предлагает изменения расписания; применять их можно только после выбора и подтверждения пользователя. Не сообщайте о настоящем подключении внешнего сервиса, пока оно не выполнено. Пользователь разрешил Google Calendar OAuth, просмотр, создание и изменение событий основного календаря. Вход — один аккаунт владельца с логином и паролем. Для Vercel требуется постоянный PostgreSQL, а не файловая SQLite.

13 октября пользователь разрешил объединение в main и production-выпуск после усиления безопасности. PR #1 объединён. Ritm опубликован на https://ritm-eta-hazel.vercel.app, проект Vercel ritm использует Neon Free ritm-db, миграция001 применена. Проверены публичный HTTPS, вход/выход и CRUD задач на настоящей базе. Позднее владелец настроил Google OAuth и OpenAI: Google status connected подтверждён через production API, ответ ИИ с событиями показан пользователем. Пользователь также явно разрешил постоянную автопубликацию push в main: GitHub аккаунт и доступ приложения Vercel подключены, проект связан с Kyjoki/Ritm, productionBranch=main. Конкретные изменения дизайна входа пока не поступили. Календарь по просьбе владельца начинается с воскресенья; подписи времени AM/PM, внутренний формат HH:mm.

Для приватного репозитория на Vercel Hobby автор релизного commit должен соответствовать владельцу Kyjoki. Новый commit можно создать через его авторизованный GitHub connector с автоматической атрибуцией владельцу и Co-authored-by Codex; проверяйте возвращённого автора до обновления main, используйте expected_sha и force=false. Локальную Git identity и старые commits не переписывайте. GitHub Actions и Vercel Git deployment выполняются параллельно; перед обновлением main выполняйте необходимые проверки, затем подтверждайте состояние production конкретного Git SHA.

Последующие правки календаря: 48px на час, начальное окно 9 AM–9 PM и прокрутка к остальным часам, текст карточек сверху, без G. Цвета 1–11 выбираются в форме; для Google сохраняются через colorId, для Ritm — в JSON задачи. Личные экземпляры Google-повторений можно редактировать по конкретному instance ID с If-Match; родительская серия и сложные/защищённые события остаются только для просмотра.

Уточнение владельца: Ritm и Google — один календарь с двусторонним обновлением. Уберите выбор источника записи: создание, изменение и удаление календарных записей выполняются в Google primary. Видимая страница обновляется каждые 30 секунд, при возврате фокуса и после записи. Старые незавершённые задачи с датой переносятся через устойчивый receipt и детерминированный Google ID; локальную запись удаляйте лишь после подтверждения Google и проверки исходной версии/часового пояса/подключения. Задачи без даты и история выполнения остаются локально. Не обещайте мгновенную доставку изменений или редактирование событий, ограниченных Google.

По следующему запросу добавлена полная палитра из 24 цветов. Для 13 дополнительных оттенков используются native Google labels, не локальная имитация или ближайший цвет. Дополнительный scope calendar.calendars запрашивается только по явной кнопке «Разрешить новые цвета»; текущий grant сохраняется до успешного consent. Чтение не создаёт метки. Запись добавляет только выбранную метку через merge существующего массива и If-Match; календарные настройки и прежние labels не заменяются. При редактировании без смены цвета поле цвета не отправляется.

Дополнительная задача 13 октября — усиление защиты от распространённых веб-атак. Код проверен по OWASP, усилены вход/cookies/Host, ограничения HTTP/ИИ/данных, исходящие OpenAI-запросы, AES-GCM и CI. Для проверки production до promotion разрешён только точный VERCEL_URL текущего deployment, без wildcard. Отчёт `docs/security-review.md` описывает реальные барьеры и ограничения; не обещайте полного иммунитета от атак. Правило Vercel WAF подготовлено в `docs/vercel.md`, но на платформе не включено. Проверяйте привязку проекта и окружение до миграций/выпуска; не выводите секреты.

Новое уточнение владельца: слева в «Мой день» — список задач на сегодня с выполнением и быстрым добавлением, справа — расписание. Быстрые задачи имеют calendarEntry=false и дату дня; сохраняются локально на сервере, не показываются в календаре и не переносятся в Google даже после редактирования/восстановления. Не добавляйте SQL-миграцию для флага: задача уже хранится в JSON. Отдельный opt-in Google Tasks запрашивает scope tasks, сохраняя Calendar и палитру. Выполнение связано с проверенной личной задачей Google по точному webViewLink, полному названию, дню, единственности ссылки, ETag и OAuth-версии. Реальные календарные представления задач владельца имеют focusTime; это кандидат связи, а не неизменяемый признак задачи. Обычные события, приглашения, повторения и неоднозначные связи не дают действия выполнения. Сохраняйте Calendar-время: Tasks API его не поддерживает. Не выдавайте локальную галочку или неизвестный статус за подтверждённое выполнение в Google.

14 октября владелец добавил русский и английский языки. Используйте общий I18nProvider и каталоги src/locales для интерфейса/ARIA; новые подписи добавляйте сразу на двух языках. Settings.language=ru|en сохраняется в существующем JSON; после сохранения меняются интерфейс, форматы дат и язык будущих ответов ИИ. Имена, названия, описания и старые сообщения не переводите. API получает Accept-Language для ошибок; предпочтение аккаунта задаёт язык новых оценок. Воскресенье первым и AM/PM сохраняются.

Обсуждение идей продолжает конкретный сохранённый отчёт через reviewMessageId. Сервер определяет исходную идею, цепочку уточнений и номер оценки; эксперты получают только собственную предыдущую оценку, без оценок других ролей и других диалогов. Общий вывод сравнивает новую оценку с предыдущей. Старые отчёты не изменяются. «Новая идея» явно снимает контекст; обсуждение не читает календарь и не предлагает действия над расписанием. Сохраните лимиты контекста, повторов и платных запросов; не обрезайте уточнения без сообщения пользователю.

«Финансы» — личный ручной учёт доходов, расходов, депозитов и акций с графиками. Валюта по умолчанию KZT. Суммы разных валют не складывать без проверенного курса. Стоимость активов — введённая владельцем оценка, а не котировка в реальном времени. Финансовые данные не передавать ИИ или внешним финансовым сервисам без отдельного решения пользователя.
